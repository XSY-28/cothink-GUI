# Pi 插件直接兼容方案

日期：2026-10-30，按用户澄清修订。2026-10-31 状态更新：消费方已实现有边界的安装、动态工具、技能／助手及基础交互；实际验证和未验边界见 [VALIDATION.md](../../../VALIDATION.md)。本地候选未发布，agent-sync 内核不变。

## 1. 用户目标与本次决定

从 Pi 官网插件目录复制 `pi install …`，只将命令首部换成 `cothink`；安装后实际使用技能和插件工具、命令、事件，不要求用户逐包改源码、加入哈希白名单或手工列出工具名。安装成功不能代替功能可用。

每个模型都能使用已安装技能；工作时主、副模型及插件子代理可通过已安装的 subagent/agent-teams 插件创建助手，结果交回创建者，最终沿用 agent-sync 整合。用户已说明旧禁令是早期取舍，现予撤销；不再把“是否解除 subagent 禁令”作为待审批问题。技能能力、父子协作与版本接纳是不同职责，不构成必须二选一的架构冲突。

本文遵循修订后的 [设计基线](../../../DESIGN_BASELINE.md)。普通问答仍为 ONE 一次／CoThink 三次，不因安装插件自动派生工作。为落实“每个工作模型”，本方案采用 ONE 仅有一个 Team 负责人、工作时也能使用插件助手的语义：不启用 Team 评审和正式副模型，助手仍须显示和记账；用户明确要求无子代理时禁用。该语义已按后续实现落实，普通纯答一／三次保持；具体证据不由本文设计推断。

Team 原有同模型占用限制保留在正式成员层，不能用另起正式成员绕过未知结果；插件助手可使用相同模型，但必须有独立会话和明确父子身份，不冒充新的独立评审。本段保留设计约定；README、AGENTS.md 和提示词已随实现同步，当前候选与历史发行证据分别记录。

## 2. 路线与兼容范围

采用 Pi 原生插件机制，并在 CoThink 衔接任务生命周期和成果接纳。移除常规使用中的逐包白名单；优先复用 Pi 公共 API，不建另一个插件市场或模型运行底座。

全量隔离代理会改变任意 Node 行为和终端 API，不作为默认路线；继续逐包人工审批也不能实现用户期望。实际插件需要不同接入方式时由 CoThink 处理，不能把繁琐适配转交用户，也不能把尚未支持的路径写成已经兼容。

主要验收入口是终端 `cothink`。CLI 与 GUI 共用资源，GUI 映射可支持的通知、选择、输入和工具结果；任意原生终端组件不能直接当网页组件，须显示实际支持情况与终端入口。外部凭据、原生依赖、插件自身缺陷和未来 Pi API 变化仍需按事实处理。

安装从官网 npm 命令贯通，再覆盖 Pi 的 Git/URL/本地来源及个人/项目作用域，逐项核对路径、信任与重载语义。用户主动安装的扩展按原生代码运行，依赖脚本不能静默跳过后报告完整可用；候选回退仅能恢复受管安装文件，不能声称撤销任意脚本的宿主副作用。

官方来源：[插件目录](https://pi.dev/packages)、[包管理](https://pi.dev/docs/latest/packages)、[扩展接口](https://pi.dev/docs/latest/extensions)。实施以锁定 SDK 及实际插件版本为依据，官网 latest 不自动等于当前 Pi 1.4.0 能力。

## 3. 开工前实现与缺口（2026-10-30 历史）

- [packages.js](../../../src/packages.js) 当前只接受 npm、关闭依赖脚本，发现与登记均排除 extensions，并拦截 subagent 类包名。
- [pi-runtime.js](../../../src/pi-runtime.js) 固定纯 UI 哈希审核、拒绝 extraToolNames、限制可激活工具；仅改资源 enabled 不足以支持工具和动态注册。
- [workers.js](../../../src/workers.js) 已向成员传递任务包快照和技能正文，但并不等于成员能读取全部技能引用、执行脚本或使用扩展工具；需检查各角色实际资源路径、工具权限与生命周期。
- [workspaces.js](../../../src/workspaces.js) 将内置文件与 Shell 工具接入 agent-sync。插件自行启动的 Pi 进程不会自动继承这些适配，也不会自动进入 CoThink 的取消、状态与用量记录。

## 4. 每个模型如何使用技能和助手

### 技能与插件资源

主答、评审、工作领导、正式成员和插件助手均能获得当前任务选定的技能来源；自动预载的正文继续冻结。“预载只读主文件”仅约束预载过程，工作中的执行者可继续读取引用并使用工具和脚本。普通纯答角色不因为技能含脚本就自动获得写权限或额外模型调用。

在 Pi 加载器接入工具、命令、快捷键、事件和 provider，覆盖动态注册、重载、冲突及错误显示。资源共享不等于会话和运行状态共享；服务按插件的生命周期创建并清理，不机械重复触发主会话副作用。子代理使用正确的 CoThink 数据根、配置与资源，不能默认从 PATH 启动无关的全局 Pi 配置。

### 父子归属、状态和取消

复用现有任务、会话及请求记录，以原任务、父执行者、插件实例和子代理 ID 标识归属；保留实际模型、目录、调用、结果与状态。父子关系由 CoThink 管，不添加到 agent-sync 协议。

子代理的结果先回父模型，父模型负责审阅和继续整合。允许有任务理由的嵌套协作；复用插件已有的并发/深度设置及用户约束，阻止无进展自我派生，不将工作 maxCalls=null 偷换成未告知的硬额度。助手数量、额外请求和已知用量可见，未知费用保留未知。

取消任务要沿父子链停止新派生、取消请求并处理相关进程；无停止凭据时显示未停止或未知，不提前报告完成。重开后核对遗留会话、进程和未知请求，不自动重发。插件若只有独立进程而无标准生命周期事件，需结合其进程句柄或公开接口适配；本设计不假定任意插件都提供统一取消 API。

### 文件成果归集

默认以父执行者的既有 change 汇总助手成果；复用 CoThink 的串行写入队列。需要并行工作的助手使用各自独立副本或受控工具，不直接共享可写目录。父模型持有范围时，不能让孩子再申请重叠范围、同时父模型等待孩子，造成自锁。

支持受控工具的插件可经 CoThink 转接现有 read/edit/exec。使用原生文件工具的插件使用独立的普通工作副本或必要的独立仓库副本；绝不把 agent-sync 内部投影、原工作目录或正式 ref 当作自由写入位置。插件自己的提交只属于候选材料，不能直接成为正式接纳。

副本产生于固定的父 change 私有版本。复制前通过公共 read 按实际可见范围登记读取依据；同一 change 的材料化过程与写入串行，或逐次校验返回版本，不能混用多个版本。无法观测插件具体读取时保守登记整个交付范围；这可能增加刷新与冲突，必须如实保留。历史 version-only read 不登记依赖，不能单独替代此步骤。

交回成果时先停止相关写者并固定文件快照，再核对实际 delta、读写范围、源路径/链接类型、输入版本和旧内容哈希。CoThink 将合法新增、修改、删除及可执行位转换为公共 edit 的 edits，携带 expectedVersion、oldHash 和已保存 requestId。父草稿已变化时拒绝直接套用旧结果，保留双方材料并重新核对依据；不能只换成新 expectedVersion 掩盖过期输入。同一父 change 的多个结果依次整合，后到结果必须重新核对。

父模型审阅汇总内容，CoThink 调用 prepareChange 固定候选，再调用 acceptChange 检查最新组合并接纳。失败、越界、冲突与未知结果保留，不能自动降级成直接复制到原目录。纯文本成果回到父模型即可，不为了记录文本强建 change。

副本是成果管理手段，不是 OS 沙箱。原生插件仍可能有其他宿主副作用；不能声称所有插件动作均由 agent-sync 隔离或取消。插件生命周期与文件路径是否可控须在真实接入中验证，不能用提示词承诺代替。

## 5. agent-sync 是否需要修改

**按上述方案，当前没有证据要求修改 agent-sync 内核；先修改 CoThink 消费方。** 这是源码接口审查结论，尚非真实插件接入已通过的结论。

具体模块、生命周期、文件导入、取消恢复与施工验收见 [CoThink 中的 agent-sync 接入修改计划](../plans/2026-10-30-agent-sync-plugin-integration.md)。本节保留职责与接口结论，接入施工细节由该计划维护。

| 需要的行为 | 已有接口或归属 | 本次结论 |
| --- | --- | --- |
| 父子任务、模型、资源与取消 | CoThink 任务/会话与插件生命周期 | 改 CoThink，不要求内核认识子代理 |
| 写范围与冲突等待 | beginChange、refreshChange、scope/readScope | 沿用；父子归集避免重叠申请死锁 |
| 固定输入及读依赖 | read(changeId, path, kind)、返回 version | 可构造可核对的插件副本；复制也须登记读取依据 |
| 外部文件结果进入草稿 | edit(changeId, expectedVersion, edits)，逐文件 oldHash | 已支持新增、修改、删除、普通/可执行文件；不必新增任意目录导入 API |
| 候选、最新组合与唯一正式版本 | prepareChange、acceptChange | 沿用正式检查、冲突检查和条件更新 |
| 失败、未知与恢复 | inspect(requestId)、refreshChange、abandonChange | 内核动作沿用；插件进程回收由 CoThink 另行完成 |

源码依据：[内核实现](../../../packages/agent-sync/src/index.js) 的 beginChange/read/edit/prepareChange/acceptChange，[投影校验](../../../packages/agent-sync/src/git.js) 的 assertProjection，以及 [公共接口说明](../../../packages/agent-sync/README.md)。当前 edit、prepareChange、acceptChange 会核验内部投影，不能先让插件直接改投影，再要求内核信任这些变化。

若后续实际需求必须支持嵌套范围租约、外部执行器直接成为可信写入方，或公共 edit 无法表达必要成果，才以可复现案例单独评估内核变更。本轮不预先增加任务树、子代理实体、递归锁或插件执行器；也不放宽原有授权与检查来制造兼容。

## 6. 实施顺序与验收

1. **安装与加载。** 贯通官网 npm 命令、扩展加载和动态注册；取消类别禁令与固定 UI 白名单。保留版本、失败、取消、受管文件恢复证据。随后逐项补齐其余安装来源与作用域。
2. **各角色实际使用。** 通过主模型、正式副模型和助手分别读取技能引用、调用一个技能所需工具，确认主文件预载与实际使用的区别；独立评审仍符合原职责。检查重启、reload、卸载、资源冲突和加载失败。
3. **真实子代理插件。** 选一个有公开源码和版本记录的 Pi subagent 插件，记录版本与接口；从用户安装入口验证主、副模型分别派生助手、助手返回内容、状态与模型归属。增加有实际任务理由的嵌套样例，不只验证顶层 import。
4. **成果接纳。** 两个助手在独立副本工作，父模型整合后通过 agent-sync 得到正式结果。覆盖新增/修改/删除/执行位、过期输入、范围越界、无匹配搜索依据、父子重叠申请和直接修改投影的负例。证明未覆盖原目录、未产生第二条正式版本权威。
5. **取消与恢复。** 在子代理运行和写入过程中取消，确认后代停止、迟到结果不接纳、部分成果仍可查；中断后如实处理未知状态。收费信息缺失不得写成零。
6. **产品回归与候选包。** 检查 Team、普通问答一/三次、两种工作模式的助手行为、历史、GUI 支持的交互及现有 agent-sync 回归。源码与干净候选安装分别验证，修改 AGENTS.md、提示词、README、CHANGELOG、VALIDATION 的冲突说明；旧历史证据不改写。

真实第三方插件行为与本地模型 fixture 分开记录；真实收费模型/外部服务、全局切换、推送和发布按另行授权执行。Windows、物理终端和 GUI 未验项明确保留，不由一次 macOS 样例推断。最终交付必须区分已兼容、具体缺口和未验证，不能承诺未来所有第三方包永不失败。
