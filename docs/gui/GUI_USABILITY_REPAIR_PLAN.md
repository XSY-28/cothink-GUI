**状态：2026-11-09，已获用户明确指令按本文施工；源码与隔离 macOS 候选已完成本机验收，尚未替换正式安装。** 用户授权依据本轮实际 GUI 检查编写施工文档，并反复复核问题覆盖、新问题、复杂性、兼容性与灵活性。本轮实施不自动授权收费模型验收、安装替换、Git 提交推送或发行。本文提出的行为修订在实施获批前不冒充已生效基线。

## 2. 路线选择与全局约束

比较过三条路线：只改文案和按钮不能解决 F01—F06 与附件断链；重写前端、建立通用项目/素材平台会重复现有会话和权限职责；选择沿现有接口逐段修复，并只为当前缺失的输入材料增加一个有界适配模块。

- 不改 agent-sync 内核，不增加文件夹执行后端、第二个正式 ref、影子仓库同步层、消息队列或自动分类模型请求。
- 保留原调用预算、未知费用、无自动重试/压缩/预热、整条任务取消。UI 简化不等于绕过保存、身份、版本或权限检查。
- “目录已关联”“模型已配置”“环境可用”“材料已发送”“任务已完成”是不同事实；各自在发生后显示。
- 保留 Team 一级导航，不恢复最近对话占据侧栏；新增显式新对话按钮是本轮对旧“侧栏只放新建 Team”的局部修订。统一 GUI 不恢复 ONE/CoThink/PROJECT 模式选择。
- 新任务沿用完整冻结阵容、材料与技能快照；切换 Team、默认目录或阵容只影响后续选择。已提交任务不能被新 UI 状态改写。
- 创建 Team、选目录、添加材料、挑选技能、检查执行环境均不发模型请求；只有明确发送/整理/确认执行才产生相应请求或效果。
- 首批材料支持 UTF-8 文本/代码、PNG/JPEG/WebP。PDF、Office、OCR、音视频解码不在本轮新增；在选择前显示支持格式，遇到不支持类型保留其他草稿并给出转换/移除路径，不把静默忽略算支持。
- 本文规定的大小限制是文件接入保护，不改变模型输出预算；超过限制逐项提示，不截断、缩图或压缩后假称原件。

## 3. 用户路径与交互合同

### 3.1 新对话、Team 与恢复

导航顶部为“新对话”“新建 Team”和搜索；未分组对话可通过新对话按钮旁的范围菜单明确选择，无需先找到旧未分组历史。项目内“新对话”默认属于当前 Team；范围始终可见。首页直接编辑草稿，首次发送前创建未分组会话，创建确认后才发送。不得在渲染、刷新或首次加载时产生一批空会话。

已有会话新建时，保留旧选择直到新会话被确认保存。关闭失败弹层后仍留在旧会话。首次创建失败时保留首页草稿和重试/查询入口，不显示“此 Team 没有历史”。空态由已加载的会话列表与明确错误判断，不能仅看 session 是否为空。

新建阵容优先级：目标 Team 有效默认 → 当前会话有效且仍存在的阵容 → 全局最近有效阵容 → 必须选择。显式失效的非空默认 ID 不静默替换：展示“原默认已不可用”，让用户选择现有组合；null 表示未设置，可使用后两项。创建参数新增可选 sourceSessionId/sourceLeafId；由宿主读取该来源的已保存阵容并核对分支锚及当前合法模型组合，前端不能凭显示名指定任意模型。目标默认仍具有最高优先级；来源分支漂移或阵容被删除时要求重选，不猜旧状态。首页没有来源时用全局最近。新会话界面显示本次实际继承结果；不自动修改 Team 的持久默认或任何旧对话。允许建立空对话但未配置模型时，输入保留，发送位置显示“选择阵容”，可直接打开选择器。

### 3.2 目录选择

“新建 Team”只要求名称；目录选填，用文件夹名称作为可编辑的名称建议。目录字段以“选择或新建文件夹”作为主入口，手输完整路径收进次级入口。名称约束前后端统一为 1—80 个 Unicode 字符。

原生 picker 启用 openDirectory + createDirectory，默认从当前目录或用户最近明确选择的位置打开。浏览器复用宿主目录浏览：进入已选择的父目录后才允许“新建文件夹”，不向任意传入路径递归 mkdir。创建成功后显示实际路径，取消 Team 表单不自动删除已创建的实体文件夹。

普通目录、空目录、Git 无提交目录均可关联。目录不可读、不是目录、路径失效分别显示原因；只有绑定这一步失败，不影响纯聊天。目录内有未提交修改时，明确它们尚未进入正式工作起点；不能暗中替用户提交。

Team 菜单有“更换默认目录”“解除默认目录”；文案说明只影响新对话。旧会话显示自己的目录，提供“按新目录开始对话”，不自动改旧会话的 cwd、计划、任务或文件授权。整个目录实际移动后的旧执行任务保留旧执行绑定，不把重定位当成正式版本迁移；未恢复的旧任务需明确报告。

### 3.3 输入与添加

“+”菜单只含“添加文件或图片”“选择项目文件”“使用技能”，以及确实存在且可使用的插件命令入口；不显示空壳或虚构能力。无项目目录时，选择项目文件项提供“关联目录”动作，不只留下灰色按钮。

文件选择、拖放与粘贴图片使用同一导入函数。每项显示名称、类型、大小、加载状态、移除按钮；发送前失败项不能被忽略，必须重试或明确移除。同名不同内容不合并；字节相同可复用存储，显示顺序和用户选择独立。

“本次选项”与“+”分开：只读、是否委派、是否要求独立评审、请求上限。非默认选择和已选文件范围在输入区显示短标记，可打开修改或移除；不能把大段政策常驻回来。调用详细政策在选项底部按需展开；“整理上下文”放入对话菜单，点击时显示预计请求与计费，原上下文保留。

添加菜单点击外部、Esc、选定动作或切换会话关闭；触发按钮 aria-expanded 与实际状态一致，Esc 返回触发按钮，选择文件返回输入框。中文 IME 合成不发送；Enter 发送、Shift+Enter 换行沿用已有逻辑。上传期间允许继续写，不允许发送不完整快照。

### 3.4 导航、阵容与设置

顶部显示 Team 与当前对话标题，不另占大块头部。对话列表给出最后活动时间、首段用户内容摘要、草稿/运行/归档状态；两个同名对话可以区分。重命名和归档仍在行菜单，不新增对话实体。

“阵容”入口以简短当前组合名作提示；弹窗一个主滚动区，列表支持名称和模型搜索。点选组合就是切换本对话；设为此 Team 默认、调整另存、删除进入该行菜单。原阵容另存规则、旧快照和删除限制不变。模型选择器复用现有模型目录，按名称/provider/id 搜索，显示认证缺失/不可用原因，不引入另一份模型配置缓存。

设置保留现有类别。技能以用途、来源、是否可用和生效范围为主；工具名、协议、版本与 hash 收到详情。项目执行先显示“未配置/待检查/可用/不可用”，有检查按钮；专业资源上限仍可编辑，不为了显得简单取消约束。OAuth 有直接登录流程；环境认证给出本机实际状态和明确说明，不要求把环境变量密钥粘进聊天。

## 4. 必须闭合的实现接缝

### 4.1 创建事务、草稿与协议

主要修改 gui/src/useGuiWorkspace.js、view.js、workspace-view.js、App.jsx、src/gui-controller.js、conversation.js、session-ui-state.js。

继续使用 creatingSessions、selectionRequest、editor editId、draftRevision、writeSelection、submissionId 与原 ID 查询，不再增建事务管理器。新建是局部 pending，旧会话在成功前可阅读，但提交冻结/禁用，避免把发送落到错误目标；新会话确认后才替换选择。用户已切换目标时，迟到成功仅进入历史，不抢回页面。明确失败允许用户重试一个新创建；结果未知只能核对原 sessionId。

首页复用原草稿簿的完整 editor，但已确认保存的草稿不能只存 localStorage：桌面随机端口会改变 origin。首次用户编辑时，在原 GUI 私有状态职责中持久保存一份 pending-home 记录（draftId、revision、完整 editor、pendingCreateSessionId、targetWorkspaceId），使用原 writer/CAS；bootstrap 读取恢复。浏览器仅缓冲尚未确认保存的输入。多窗口打开同一首页草稿沿原冲突提示，不静默相互覆盖；不能把浏览器窗口 ID 当持久身份。此记录只承担首次会话建立前的保存，不构成新会话系统。

先保存待创建 sessionId 与首页 revision，再请求 session.create；确认创建后将同一正文、材料、选项写入 session.draft，宿主确认转移且首页 revision 未被新编辑推进时才清掉 pending-home。中途崩溃按原 sessionId 与 editId 查询，不能清掉唯一副本或换 ID 重建；期间新输入留在首页记录并合并到同一新会话的后续草稿。未知结果与冲突阻止自动发送，页面刷新/完整重启均能恢复。关闭握手等待宿主保存确认；失败就保留窗口，不承诺突然断电前未确认的键入已落盘。

新增能力由 bootstrap.protocol.guiInput:2 标明；原 unified protocolVersion:1 与桌面握手 build/protocol 合同保持独立。新版 createApi 在变更请求携带 X-CoThink-GUI-Input:2，gui-server 在分派写操作前校验，缺失/不匹配返回可恢复的升级提示，GET 历史读取仍开放。旧客户端不得在不理解材料/目录修订时覆盖新草稿。现有 unified 协议与桌面构建协议分别处理，不能只在前端放行。新记录添加 editorVersion:2；旧记录按空材料/空显式技能解释。新版宿主拒绝缺少 v2 能力声明的草稿覆盖和新增提交，仍提供旧历史读取。首次写入 v2 editor 前，在同一 session writer 下先追加并确认既有 cothink-flow unified 标记；新建 GUI 会话即标记也可，但不得等首次发送才标记。复用 src/interactive.js 的 readSessionFlow 准入，在模型/插件启动与 saveDraft 之前拒绝 CLI 继续统一 GUI 会话，给出“请在 GUI 继续”，只读历史仍可查。标记成功而草稿失败时保留标记和原草稿，不回退成可被 CLI 覆盖的 legacy 会话。新版 CLI 无需新增附件编辑器。

新版宿主的能力门控不能约束绕过 HTTP 直接写盘的旧 CLI 二进制。升级/回退前必须关闭全部旧 CLI/GUI writer；检测到占用拒绝升级。发行 CLI 与 GUI 必须使用同一新版核心；禁止宣称可与旧二进制混写。回退先停新 writer、归档升级后的完整数据根，再恢复整套升级前备份；新数据保留为只读归档，不原地降级覆盖。

### 4.2 目录能力、归属和历史

主要修改 src/gui-work.js 的检查职责、gui-controller.js 的 projectMembership/assertWorkspaceWritable/session.create/submit/runtime、gui-workspace-state.js、conversation.js。

把目录检查分两级：基础目录检查仅 canonical realpath、类型、可读性；执行检查继续使用现有 inspectGuiProject 与 agent-sync。project.inspect 可接受 purpose:'directory'|'execution'，旧无参数保持 execution 语义；返回 directoryAvailable、executionReady、reason、canonicalPath，避免用一个 valid 包办所有状态。聊天 owner/submit 只校验会话未归档、身份、单写者、配置与保存完整；需要实际读项目、提出正式工作或确认执行时才检查对应能力。

GUI 根纯答运行使用现有 neutralDirectory(home)；不改变旧 CLI 的 conversationCwd 语义。项目目标与资源来源由任务快照明确传入，不得因放宽聊天准入而偷偷加载失效路径、父目录或项目外 AGENTS/包。显式资源与个人资源继续按现有机制选择；项目资源只有目录明确、权限与快照均有效时加载；selectedResources/resolvePackageResources 按明确项目来源解析，而非随中立 cwd 丢弃项目技能/包。目录失效时显示此次不可用的项目资源，只保留真实可用的个人/内置资源，不静默假称完整能力。普通目录不能通过 allowWork:Boolean(path) 直接获得原生工具。

导航成员关系按显式 workspace UUID 判断；会话里的 cothink-project 保留创建时路径。二者目录不再必须相等，但实际执行仍逐任务核对固定仓库/版本/权限。对没有 UUID 的旧历史，不能在重定位后再按新目录猜归属，也不能为了导航强行改写全部 Pi 分支。导航表 v2 增加仅为兼容所需的 legacyMembership 映射，键为会话 ID 与该分支保存的项目路径，值为稳定 workspace UUID；显式 UUID 优先，null 项目仍为未分组。扫描所有分支的有效项目记录，按变更前已确定的目录关系固定映射；不使用“旧路径永久别名”吸纳未来新会话。同一 session 多分支路径不同须分别解析，不用单个 sessionId 映射覆盖。

schemaVersion:2 与映射、默认目录改变在原目录表 writer/CAS 下原子发布，写前保存 v1 原字节；无法解析/被旧 writer 占用的相关记录阻止重绑定，纯聊天入口仍可用。保留原 project 字段作为“新会话默认目录”，不再维护另一个 currentProject。重定位前冻结所有受影响会话文件身份/分支叶节点，提交前重核；有变化重新读取，不能用过期扫描。旧 Pi 会话及任务字节不因导航迁移被改写。

workspace.rebind 同时提交 operationId 与 expectedRevision，沿原目录表保存本次 mutationId；结果未知先查当前 revision/mutationId/映射。若已被其他操作推进，只报告当前事实与原操作未确认，不按路径相同冒称原请求成功，也不自动重发。新增旧历史首次发现时先形成确定映射再发布；重定位后旧会话仍按映射归原 Team，不能被 discoverWorkspaces 再创建成一个旧路径 Team。相同默认目录冲突保持既有唯一性；解除目录后的同名无目录 Team 也要按原规则检查。活动工作与另一个窗口占用阻止此次目录变更；已有材料/执行任务仍按各自冻结来源读取。


### 4.3 普通目录进入正式工作

不能仅允许绑定后再在 start_work 里报 Git 错误。目录关联零副作用；目录面板及输入区目录状态提供“准备文件工作”本地动作，用户点击才盘点文件，零模型请求。若用户直接用自然语言请求工作，start_work 在生成完整 proposal 之前返回 PROJECT_NOT_PREPARED，保留本次已完成请求与原输入，界面提供同一本地准备入口，不调用只接受完整 proposal 的 task.confirmWork。准备成功后不自动续跑；“继续原任务（将新增请求）”明确提交新的 submissionId，并引用原阻塞任务及原输入，作为用户发起的具体纠错续作计账。旧任务保留 blocked；存在未知远端请求时先核对，禁止以准备动作为由另发。

选择最小路线：复用原 Git 与 agent-sync 执行链，用户确认后在所选普通目录建立 Git 起点；不另建长期影子仓库和双向同步。准备界面先显示待纳入的明确文件清单、忽略项、已有改动以及会创建的 Git 元数据。准备预览固定 author/committer、时间、message、文件路径/模式/哈希、原 HEAD/index/config 摘要、预计 tree/OID；Git 子进程剔除继承的 GIT_*，禁模板、hooks、签名和过滤器，使用参数数组。空目录可建立空初始提交；非空目录只纳入用户明确选择的普通文件。禁止无条件 git add .、加载 hook、覆盖原文件、跟随指向目录外的符号链接或自动纳入凭据/依赖目录。

原本已有有效 HEAD 的仓库继续使用同一正式 ref，不初始化、不重建、不自动提交未提交修改。Git 无 HEAD 仓库存在暂存项时，本轮不自动准备：显示具体项并保留 index，用户先自行完成/清理暂存后重查。不能声称“index 字节未变”就等于初提交后暂存语义没变。所选目录若位于父 Git 仓库内，显示实际仓库根和所选相对范围，使用既有仓库规则；禁止悄悄扩大范围或创建嵌套仓库。新建仓库用 hash-object --no-filters、mktree、commit-tree 构造已确认字节，CAS update-ref 发布；本操作独占新仓库随后按冻结 tree 建正常 index（不改工作文件）。已有空 index 的 unborn 仓库保留分支/config，确认时明确建立与首次提交一致的 index；发现并发 index/config/HEAD 变化停止。排他创建 .git，并核对 operationId 所有权，不能接管别人刚创建的仓库。身份和提交时间在预览中固定，不修改全局 Git 用户配置，不猜用用户身份署名。

准备以本次 operationId、固定所选文件路径+内容哈希、原仓库状态、预计提交树和结果 commit 保存于CoThink 私有数据根的 gui-project-preparation/<operationId>.json 中，用原 writePrivateJson 与 writer 写入。执行前重检字节及目录身份；变化则要求重新预览，不使用旧确认。未知结果按原 operationId 查询和核验 commit/tree，不重复 init/commit；磁盘写失败保留现场和具体恢复入口，不删除用户的 .git 或执行 reset --hard。仅在 HEAD/ref、冻结 tree 与预期 index 均核对后标为 ready；ref 已发布但 index 尚未完成时记录部分完成，用户点击“完成准备”才在无外部变化的情况下完成同一操作，不新建 commit。完成后再按原公共接口创建/恢复 agent-sync，后续结果仍在独立工作区，不自动覆盖原目录。

该准备入口仅为目录可开始工作服务，不扩展为 Git 客户端。具有旧 agent-sync 正式记录的目录继续走现有显式迁移流程，本步骤不能绕过迁移或制造第二条正式历史。

### 4.4 输入材料持久化与传递

新增一个窄模块 src/gui-materials.js，唯一负责接入材料字节、校验、不可变引用和读取。它不管模型、调度、权限提升或通用知识库。通过原带 Bearer/Origin 校验的 HTTP 添加二进制上传与读取端点，不把 base64 塞入现有 1 MiB JSON action。可分出一个 MaterialPicker 组件供文件、拖放、粘贴共用；不建立全局素材管理平台。

首批建议合同（名称为本轮新增接口，须实现后才能调用）：

```js
// 原 session.draft 的 editorVersion:2 扩展；旧缺省均为空。
const editor = { editorVersion: 2, text, editId, workRequest, selectionId, turnOptions,
  materials: [{id, sha256}] // 名称、类型、大小等以宿主 manifest 为准；技能沿原 /skill: 文本
};
// 上传：POST /api/materials?uploadId=<UUID>&ownerId=<UUID>，有界二进制 body；
// GET /api/materials?uploadId=<UUID> 核对结果；读取以不可变 id 为准。
// 控制器按已保存草稿读取材料；task.submit 不接受任意本机路径。
```

ownerId 绑定已经存在的 sessionId 或宿主 pending-home 已确认的 draftId；宿主回执记录归属。转入会话须在草稿转移中验证原 owner；后续只接受当前会话/祖先分支已有材料或当前草稿明确导入的引用，不能凭其他会话的 id 读图或发送。单用户本机鉴权不代替这些来源边界。

开始传字节前，先用原 action 通道的 material.begin({ownerId,uploadId,name,mediaType,byteLength,sha256}) 在材料模块登记待上传意图，并返回已持久化回执；未确认 begin 时不开始 body 上传。同 owner 的待上传意图可由 bootstrap/owner 材料查询列出，因此回复丢失或重启不依赖浏览器记住 uploadId。pending-home/editor 已完成材料仍只存 {id,sha256}，上传中项来自这份宿主意图，不伪装成可发送材料。完整字节丢失时提示重新选择同一文件并核对摘要，由用户明确继续同一 uploadId 或取消；不后台重发。

材料存于数据根内的私有不可变对象目录，先临时文件写完整并核验哈希再原子发布。id 由宿主生成，上传键保证同一操作未知时可查；同键不同内容拒绝。名称只是显示名，不作为存储路径。文本单份上限 512 KiB、图片单份 4 MiB、单条最多 8 个、总原始字节 16 MiB；文本解码必须严格 UTF-8，图片校验魔数与可解码尺寸，像素上限 25MP。不支持内容完整报错；所有上限由同一模块导出，前端只消费其 capabilities。

正文可空但至少有一个已就绪材料，发送可用。task.submit 的幂等输入摘要包括正文、按用户展示顺序排列的选择身份、材料哈希、正文中的显式技能选择和选项；复用同 submissionId 的不一致请求拒绝。草稿 CAS 检查完整 editor，后台回执只消耗当次提交快照，期间新写正文/新附件保留。上传取消不等于发送取消；未知提交期间不得移除已冻结材料的唯一字节。

纯文本作为标明来源的用户材料进入既有 Pi 消息；保留用户原问题，不把文本文件当 system 指令。图片通过 Pi prompt 的 images/content 能力进入唯一请求路径；评审、修订和后续轮次也要看到相应真实图像块，不能只把 base64 或名字 JSON.stringify 成文字。用原 request-policy 的 payloadImageHashes 检查实际发送内容；记录原件 hash 与 Pi 处理后 hash 的关联。Pi 归一化失败/丢图必须在 HTTP dispatch 前失败可见，不能用一条“图片加载失败”的提示替换后继续收费。

冻结主模型或可能接收材料的评审不支持图像时，发送前明确指出哪一个不支持，提供换阵容或移除该图；不能静默降成文字。请求正文超出模型上下文时要求用户缩小材料或明确整理，不截断原文件、不偷偷用另一模型 OCR。已发送历史保留引用与用户消息的关联；分支只继承该持久终点之前的材料，恢复与手动整理保留可追溯来源。材料丢失/哈希错误阻止依赖它的新请求并允许查看其余历史。

从草稿移除仅删除引用，不能物理删除已提交/未知任务使用的对象。本轮不增加全局 GC/引用计数系统，材料随历史保留，设置只显示实际占用。只有本次上传明确取消、未发布引用且没有未知保存结果的临时文件，才由同一上传操作清除；已发布对象不自动删。磁盘不足保留草稿并报告未接收成功，不能制造空附件。后续如需删除历史及回收，再依用户明确需求处理，不能借本轮修复新增清理产品。

### 4.5 项目材料与正文图片

“选择项目文件”提供两个明确选项：当前磁盘文件副本按 4.4 导入，不要求 Git，不授予后续访问路径的权限；“读取已保存版本”沿原 freezeReadAuthorization 固定正式版本和范围，文件树从该固定版本枚举。选择子目录显示范围与预计规模，包含未提交文件的当前副本必须逐项预览、限量导入；排除目录外链接。不得把新文件树当作扩大模型读写权限的理由。

Markdown img 不再一律占位：只接受能解析到本会话材料或对应任务固定 fileRef 的本地引用，沿原认证读取接口生成 blob URL，卸载释放；禁止 file://、任意本机绝对路径、任意 data:。远端 https 图片默认显示来源域名与“加载图片”，用户点击后浏览器直接无 referrer 请求，不做可访问内网的宿主通用代理；失败保留文字与打开来源链接。远端图片加载不代表已发送给模型。非 https 保持占位并解释。

代码块增加复制按钮，原文复制保留；与材料展示共用现有 Markdown，不另建富文本编辑器。成果文件的下载、静态预览与图片预览沿用 FilePanel，输入附件不能冒充输出成果。

## 5. 技能、认证与执行设置

首页尚无 session 时，复用 /api/capabilities 入口，以 draftId 查询宿主已保存 pending-home 的目标 Team；sessionId 与 draftId 恰选一个，目录/资源来源由宿主记录确定，不接受前端另传任意目录。返回与正式会话相同能力投影，不创建空会话；首次发送仍重新冻结校验。

显式“使用技能”读取当前会话 getSessionCapabilities/已选资源，按名称与描述搜索；展示中文简要用途和原始说明（内置项随包维护中文，外部无中文时保留原文，不为翻译发模型请求）。首批每条只显式选择一个技能，沿原 /skill:name 前缀写入完整草稿；技能标记从该前缀派生，移除只移除对应前缀，不修改用户正文，不再增加 selectedSkills 状态/执行 API。发送仍通过原冻结技能目录解析名称、读取正文与记录哈希；不存在/冲突请求前拒绝，有效来源以本次冻结结果为准。已提交任务继续用旧快照，禁自动调用技能仍允许显式选择，技能文字不扩大权限。无可用技能时提供设置入口。

外部技能设置增加“选择本地 SKILL.md 或技能目录”，调用原 piResources.skills 路径与包资源解析校验；显示同名冲突、禁用与来源信息，保存只影响新任务，不安装或执行脚本。内置与外部同名替换沿既有显式禁用流程。不增加技能市场、包安装器或新的资源注册表。插件命令菜单复用 extension.commands/command；无法在干净 GUI/PROJECT 环境执行的命令显示具体原因与现有支持入口，不把连接菜单当兼容验收。

本地命令有一张位于 GUI 边界的路由表：/settings 打开设置，/team、/models 打开阵容，/help 显示 GUI 帮助。已取消的模式命令提示“此界面已统一处理，直接描述任务即可”；未知单行 /命令不发模型，提供可用命令或“作为普通文字发送”显式动作。多行材料中的命令仍按材料保留。插件命令与 /skill: 继续按实际注册能力分派，不能另做一个大语言模型路由。

OAuth 使用 createModelRuntime 返回的现有 ModelRuntime.login(providerId, type, {signal,prompt,notify}, options) 与 Pi 凭据存储；按 SDK AuthInteraction，prompt 处理 text/secret/select/manual_code，notify 处理 auth_url/device_code/info/progress，适配原 GUI 弹层，不猜旧版 onAuth API。宿主拥有登录操作、取消和结果，GUI 只显示授权地址/短码/必要回调输入，使用已有受信外链打开方式。不在 renderer 保存 token，不把 CLI 子进程嵌入页面，不并行开启同 provider 的重复登录；关闭弹层取消等待，保存已完成则明确告知。首次实现先用 SDK 回调 fixture 验证，实际 provider 授权由用户在系统浏览器完成；SDK 未提供所需回调的 provider 只显示准确不支持范围，不宣称所有 OAuth 均已接通。

执行环境检查在 CoThink 宿主的 gui-settings.js 沿已有受控子进程方式实现，不越过公共接口 import agent-sync 私有 executor.preflight，也不把公共 inspect 返回的已保存配置当成已执行检查。第一步只读诊断本机 Docker endpoint、daemon、镜像存在及固定 digest；第二步在用户点“检查执行环境”后，用已存在镜像和固定无项目文件的最小容器探针验证基本启动/退出/清理，不拉镜像、不运行用户脚本、不自定义挂载或放宽网络/资源限制。两个步骤分别显示，第二步未通过不能标成“可执行”。这只证明基本环境，项目特定检查仍在实际执行时核验。

检查结果带时间与配置摘要；配置变化立即失效，保存配置不等于检查通过。错误给“启动 Docker 后重查”“选择已在本机的镜像”“配置不可用项”，保留展开诊断；本轮不建设自动 Docker 安装/镜像发布系统。使用项目当前约定的本机 Docker 连接方式；外部/远端 endpoint 不作为桌面“本机可用”成功，报告具体边界。
