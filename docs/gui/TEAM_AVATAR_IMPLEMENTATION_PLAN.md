# CoThink GUI Team 头像施工文档

配置本地素材后，当前 Team 默认头像是巴巴祖。角色选择、左栏尺寸、图标和名称显示位置的后续调整见[当前设计基线](../../DESIGN_BASELINE.md)。下文保留初版头像方案及验收边界。

> **状态：2026-11-09，源码已实施，通过本机 Chromium 与桌面验收，已安装到本机正式路径。** [验证记录](../../VALIDATION.md#team-头像本机安装2026-11-09)区分源码、打包与正式安装。先读[当前设计基线](../../DESIGN_BASELINE.md)、[Team 导航修正](TEAM_NAVIGATION_REFINEMENT_PLAN.md)和[基础使用路径修复](GUI_USABILITY_REPAIR_PLAN.md)。

**目标：** 按用户描述的 Grok Bot 体验，左栏 Team 默认显示圆角方头像，移入头像即播放，停留约 2 秒才显示 Team 名称，移出复位；主对话同一 Team 的回复用相同角色的圆形静态头像。使用用户确认的巴巴爸爸素材和原动作。

**落点：** 私有 `cothink-gui-workspace` 的 `0.8.14-desktop.3` 源码。本文所在的 `gui-usability-repair-local` 工作树与正式 App（build ID `9f4311c606ff65232ba08b86c54aca316136572c5a8bb6388e3b41bef09e7ab9`）内的导航、对话、会话选择、归属和静态服务器相关文件已逐字节比对。常用 GUI 目录仍是 `desktop.2`，不能用它覆盖新版导航；旧 `cothink-v2` 不作为 GUI 施工入口。开工时以当时接续的真实源码重核接缝。

## 1. 用户能看到什么

| 场景 | 约定 |
| --- | --- |
| 左栏静止 | 每个活动项目 Team 显示一个圆角方头像；默认建议 32px，圆角约 7px。完整胸像贴住底板下沿，底角收进圆角。**Team 名和同名目录提示默认隐藏，选中的 Team 也一样。** 保留选中态、必要的真实状态和现有点击入口。 |
| 左栏悬停 | 鼠标或触控板指针进入头像区域后立即开始动作（图集就绪时从第 0 帧开始），连续停留满 **2 秒**才在头像旁显示名称；同名时一起显示原有短目录提示。动作按素材原时长循环，手臂、耳朵或道具按原画越过底板。移出即隐藏名称、恢复静态图；快速扫过多个头像不显示任何名称。悬停不选 Team；点击照旧。 |
| 主对话 | 已有可见回复正文时，在本轮回复头的用时之前加约 24px 圆形静态头像。它表示这份回复所在的 **项目 Team**，主答、评审或实际执行者的身份仍在“查看过程”。同一角色与左栏配对，鼠标放上去也没有动作。保留用时、完成／失败等状态和正文网格。用户消息、空对话、只有运行／失败提示的空结果和过程面板不加头像。 |
| 键盘、触屏、减少动态 | 导航行仍是原有单一按钮，始终可读出 Team 名，焦点及 Enter／Space 可用。键盘聚焦或触屏点按不触发左栏名称或动画；可从现有搜索按名称及同名目录选 Team，打开后主区照常显示 Team 名。系统“减少动态”只关闭动画，鼠标停留 2 秒仍显示名称。 |

这是对旧设计里“左栏常驻 Team 名”和“移除回复头虚线圆圈”的局部修订。仅左栏 Team 列表改为头像和延时名称；回复头继续保持精简。保留 `desktop.3` 的侧栏宽度、新对话、未分组、主区 Team／会话标题、阵容、搜索、添加材料和设置。

## 2. 素材和角色选择

本机素材包于 2026-11-09 确认。素材 README、`review/preview.png` 和渲染示例是底板、取景、手臂越框及原帧时序的参考；触发方式按第 1 节。预览示例的键盘聚焦播放和触屏指针事件不带入产品。

仓库保留头像渲染代码和位置清单，图片由本地构建提供。要构建带巴巴祖头像的版本，将获准使用的三张配套 PNG 放到 `gui/src/assets/team-avatars/assets/barbidou/`，然后运行 `npm run build:gui`。缺少这些文件时，侧栏和 Team 回复使用内置占位头像。

| 文件 | 用途 |
| --- | --- |
| `assets/<角色>/sidebar-foreground.png` | 256×256 透明静态胸像。图集第一帧与它不同，不能代用。 |
| `assets/<角色>/sidebar-motion-atlas.png` | 水平排列的 256×256 完整动作帧。按 `durations` 与 `sidebarPlacement` 绘制，保留每帧越框开口及曲线。 |
| `assets/<角色>/chat-static.png` | 128×128 已取景的静态圆形 PNG。对话直接显示，不从左栏重新裁图。 |
| `manifest.json`、`originals/sources.json` | 前者保存资源路径、时长和绘制参数；后者保存官网来源、原始帧资料和 SHA-256。 |

清单有十个角色、30 张 PNG、31 格悬停素材。巴巴利波 `barbotine`、洛丽塔 `lolita` 各只有一个悬停姿势。**首版默认池用八个有多帧动作的角色**，让每个正常 Team 都兑现“移入会动”；两位单姿势角色留在素材包，不加伪造动作。八组 PNG 约 695 KB（694,766 字节，未计清单）；未来若接入单姿势角色，沿用独立静止／换姿势合同，并另行决定是否放进默认池。

首版无需先给每个 Team 手工设置。只用现有 `workspace.id` 确定默认角色：以小写 UUID 的 ASCII 字符运行 32 位 FNV-1a（初值 `0x811c9dc5`，每字节异或后乘 `0x01000193`，用 `Math.imul`，结果按无符号解释），取余后查下面的固定默认池：

```text
barbapapa  barbamama  barbabelle  barbalala  barbibul  barbidou  barbidur  barbouille
```

改名、重排、换阵容、绑定或更换目录、归档恢复、重启都不换角色。允许不同 Team 分到同一角色；通过延时名称、同名目录提示或现有搜索区分。默认池的顺序和槽位视为发布后的约定；新增素材不改变旧分配。若未来确实需要手选或保证唯一，再给同一个角色解析入口加显式选择；届时另做保存与迁移决定。首版不创建头像设置、分配表、模型到角色的映射或用户上传入口。

本次核对的清单 SHA-256：`670308b684d56eff600efef4dc75f815297cbefc2c78687b533fd1651568109c`；ZIP SHA-256：`abc540b60192dc699e4d37973a848e188f8b2b7aa762f50a4aa8ef1a32cfd878`。素材记录了官网出处，包内未见分发授权。施工验证可在本机隔离工作树和候选使用；素材原件和试用证据留在本机。若后续要将角色图像提交到共享仓库或随包分发，先核对相应授权，或换成可分发的同规格素材。

## 4. 动作和布局的实现合同

1. **复用原图取景。** 参考素材 `avatar.js` 的逻辑画布（256×256）、中心底板（128×128，坐标 64 至 192）、`sidebarPlacement`、静止圆角裁剪、悬停 `motionOutlets` 和曲线开口。每次绘制一张完整帧；在底板以外只放行清单指定的部分。不要把整个画布塞进圆角 `overflow:hidden`，也不要叠两张胸像假造越框。
2. **给动作和名称留位置。** 以 32px 底板起步，行内左留至少 16px，底板与名称区之间至少 16px，行高约 44px。同名目录的第二行预留在名称区，显示和隐藏都不改变行高、滚动位置或点击区域。八个图集的透明度边界换算到 32px 底板，裁剪前约为左外 14.0px、右外 14.5px、上下各不足 2px。长名称只在自己的区域截断，完整名称可通过搜索或打开 Team 查看。保留侧栏滚动裁切；完整可见的首行、末行和窄栏须保住实际越框像素。画布 `pointer-events:none`，越框不扩大悬停区域，也不盖住名称、状态或相邻行。
3. **让失败只影响对应头像。** 静态前景和动画图集分开解码，图集在首次有效悬停时才请求，同一角色共用解码结果。加载图集期间仍显示静态图；图集缺失或尺寸、帧数与清单不符，保留静态图。静态前景缺失或 Canvas 不可用时，先用该角色的圆形图放入方形底板；若圆形图也不可用，显示同尺寸的中性占位。对话图加载失败直接就地占位，列表仍可点、历史仍可读。头像请求失败不触发会话刷新或模型调用。
4. **同一次悬停，分别控制动作和名称。** 在原按钮内用固定的头像区域接收 `pointerenter`，只接受 `pointerType === "mouse"`（含触控板）；名称出现的区域不扩展触发区。有效移入即启动局部 2 秒计时，同时独立加载或播放动作；计时按本次悬停的 `workspace.id` 核对，图集失败和减少动态都不推迟名称显示。只在该行原有文字位置显示名称和短目录，不增设全局提示框。指针离开／取消、点击选中、窗口失焦、页面隐藏、导航不可交互、行滚出视口或卸载时清除计时与名称，并停播复位。计时到期、异步图集解码后和活动帧回调都复核当前头像、有效悬停、可见性和祖先 `[inert]`，覆盖[桌面关闭保存时直接禁用 body](../../gui/src/App.jsx#L75) 的路径。恢复交互后等下一次实际移入。动态偏好切换只控制动画；最多一行播放，按原时长累计选择帧，只在帧号变化时重绘。

采用现有图集加局部绘制，是因为只做 CSS 动效或替换成原 GIF 会失去已确认的取景和越框；统一设一个吉祥物虽更简单，却少了 Team 间的识别提示。保存可编辑的头像字段会支持精确选择，但现在无需为默认头像增加迁移与管理流程。角色数据、绘制方式和业务身份各自独立；更换一组图或停用动画无需改历史和模型。

## 5. 施工顺序与验收

- [x] **A1：素材与静态路径。** 确认版本和素材哈希；导入八套 PNG 和对应清单。先接通两处静态头像及降级，再用同阵容的不同 Team、改名、换阵容、关联／更换／解除目录和重开历史，验证两个位置始终根据当前会话的真实归属成对显示。另测待创建、快速切换、跨 Team 搜索及分支，归档历史、未分组和归属异常。身份测试使用固定、映射到不同角色的 Team UUID，例如 `7c8094cd-3476-4bfa-8f53-000000000001` 和尾号 `0002` 分别为巴巴祖和巴巴布莱特；对两处分别核对预期角色，避免同角色碰撞掩盖串队。
- [x] **A2：侧栏动作与延时名称。** 核对八位角色首帧、时序、复位及越框；逐帧查看巴巴妈妈的手腕、巴巴布莱特的向左伸展、巴巴伯的向右伸展及巴巴布拉伯的举重。浏览器验证：初始和选中时无可见 Team 名，进入头像即能开始动作，2 秒前仍无名称，持续停留到期仅该 Team 显示名称，移出即隐藏。同名时目录同步出现。快速扫过 A／B、到期前点击、滚出、关闭抽屉或打开模态都不能留下延时名称；名称显示不挤动头像、状态或相邻行。验证减少动态、触屏、键盘、图集加载迟到／失败和真实状态可访问性；减少动态和图集失败仍应在鼠标停留到期后显示名称。圆形回复在鼠标悬停及侧栏完整播放周期内保持同一静态文件和相同像素。
- [x] **A3：浏览器组合验收。** 复用 [GUI 组件检查](../../test/gui-components.test.js) 和 [真实 Chromium 导航场景](../../test/gui-navigation-visual.test.js)；用实际 HTTP 路径与既有离线数据，不新增测试框架。将组件用例中“选中行正文包含 Team 名”的旧断言改为检查可访问名称、真实状态和默认无可见名称；浏览器检查实际 2 秒延时。保留现有 UI 新建测试，另用宿主的 `workspace.create` 动作准备固定角色的 Team。至少三个 Team 验证身份，用足够多的行触发滚动。覆盖浅／深色、1280px 固定栏、800px 窗口下打开抽屉、长名称／同名目录／状态同在、首末行；也用键盘或触屏在搜索中按目录选中正确的同名 Team。对静止、两个不同动作帧、延时名称、移出及静态回复截图或录屏；用画面差异确认实际动作。保留现有标题、键盘、草稿、用时、文件操作及零生成断言。
- [x] **A4：候选验证与文档。** 用现有桌面脚本打包到新的 `.noindex` 目录；按 `desktop/runtime-manifest.json` 的锁定哈希传入 Node 和 Electron 归档。现有[实际 Electron 候选检查](../../test/desktop-app.test.js)只准备草稿；为头像用例在临时数据根沿用 [Chromium 的已保存回复夹具](../../test/gui-avatar-visual.test.js#L44) 准备一条离线历史，再在真实候选复做悬停、复位和静态回复。核对同源 `image/png` 响应、图像解码尺寸、包内文件和启动无资源错误。记录实际包体增量，npm 包同时包含 GUI 源文件和构建产物。源码浏览器通过不代替候选验收。落地后用 doc-maintenance 同步 [Team 设计](TEAM_WORKSPACE_DESIGN.md)和[桌面视觉约定](DESKTOP_UNIFIED_IMPLEMENTATION_PLAN.md#51-视觉精修)受本轮修订的条款，并把验证写入 [VALIDATION](../../VALIDATION.md)；若随版本交付，再按项目约定更新 README 与 CHANGELOG。

## 6. 文档复核与剩余验证

| 复核时发现的差距 | 本方案如何关闭 |
| --- | --- |
