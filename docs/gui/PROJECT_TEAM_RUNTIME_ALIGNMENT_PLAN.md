# CoThink GUI 全量审查与协作改造方案

> 2026-11-10 按用户手稿与后续说明修订，补齐依赖调度、文档控量和真实组队验收。实施按下方任务顺序使用 executing-plans 或 subagent-driven-development。每项交付通过对应入口验收后再勾选。

依据 [当前设计基线](../../DESIGN_BASELINE.md#目标与最小路径)。用户在项目 Team 的对话中选择一主、至少一副的阵容，由主模型作为经理。简单任务由经理直接交付。复杂任务由主模型按能力组队并决定层数，通常三层、最多四层，过程检查员不计入层级。主模型或副模型可担任负责人、员工和独立审查员，同一型号可同时承担多个岗位。领导为下属选择和概括材料，主模型可补充。组队期间定时检查每位员工，异常逐级上报，领导按需返工、增组或暂停结清。文件协作经 agent-sync 管理，经理将最终成果带回主会话。

本方案沿用 React/Vite、Electron、本机 HTTP/SSE、Pi SDK、正式 PROJECT 和 agent-sync。建议替换 GUI 新任务的旧路由和交付规则，复用现有阵容、任务账本、岗位、独立会话、授权和版本机制。

## 3. 路线选择与施工约束

仅删复选框、给 `start_work` 补说明，能减少鹈鹕式失败，仍会留下旧后端路径、无法组队的只读任务和拼接式交付。另建协作运行时需要重复实现权限、用量、停止、历史和结果校验。现有正式 PROJECT 已有同型号并行岗位、直属分派、固定候选审查及版本接纳。四层管理扩展现有父子授权链，周期检查复用席位和请求准入，就绪任务沿同一 PROJECT 调度器领取。因此改造 GUI 入口和投影，并将需要复用的协作逻辑从已有机制中提取。只有现有公开接口无法表达具体的授权或结果，经复现后才考虑改变接口。

- GUI 新对话只有一条经理入口。首个主模型请求理解任务并决定直接答、组队或提交文件计划。明确文件意图只确定交付义务。用已有保守识别与草稿标记，模糊请求交给经理判断，无额外分类请求。主模型可先读材料再决定组队。独自做文件仍走正式文件工具和权限检查。
- 文件修改沿用确认后的作用域、输入版本、检查和接纳。既有 agent-sync 公共接口继续提供写入权限及唯一正式版本线。模型、技能文本、材料和工具输出均不能扩大授权。
- 区分“只分析，不修改”和“禁止派工”。只分析限制写入，禁止派工阻止新委派。禁止派工与具体成果已有的独立审查要求冲突时，按冲突处理，不能把必要审查静默降级为自检。读取范围、预算和离线选择按当轮授权处理。已确认方案和历史任务按原约束、预算、版本和请求身份恢复。新 GUI 发送使用新规则，旧 CLI 按对应版本保留。
- 每次物理请求由统一策略准入和计数。确认前的经理与只读岗位请求从正式执行的额度中扣除，沿用已有提议和确认回执，最终汇总也从同一逻辑轮次余额扣除。取消覆盖实际参与者，未知请求继续查原身份。
- 以已持久化的根任务、工作分派和正式版本为事实来源。只读岗位可用根任务内的独立阶段和 Pi 会话，正式文件岗位沿用 PROJECT 登记。共享调度准入、席位和停止规则，投影两类实际记录。前端不另存调度状态，agent-sync 仍是文件写入和接纳的唯一权威。
- 岗位深度、临时小组数量和在途请求席位分别管理。主模型仍是调度决策者。宿主负责依赖就绪、席位、权限和真实协作回执。优先在现有任务、岗位、请求及交付记录补信息。检查计时器只通知到期，调用、权限、停止和恢复继续共用一个调度与账本。
- 用户可在会话中查每个岗位的任务、实际执行模型与结果。阵容是可用候选。岗位仅来自已登记分工或实际请求，不由标签推断。

## 5. 设计复核与通过条件

| 用户要求 | 施工与可观察验收 |
| --- | --- |
| Team、对话阵容和简单直答 | T1、T6。同 Team 的两条对话可各选一主、至少一副，历史与分支还原快照。简单文字与图像任务只有主模型请求 |
| 经理按能力组队 | T3、T4、T7。通常三层、最多四层，核对直属授权、独立岗位会话、同型号并行及实际技能使用。明确承诺和自主决策分别验证 |
| 独立工作并行、阶段重组、跨天接续 | T3.3。A/B/C 重叠，D 只等 A 且按任务重新选人。重开查询零请求，明确续作只派已核对的剩余工作 |
| 定时检查、上报和暂停 | T3.2、T4。实际检查覆盖执行员工。阻塞逐级报告、有权领导增组。暂停与发送、接纳竞争时封口并用原回执结清 |
| 选择性上下文和必要时查过程 | T3–T5。岗位只收到获准材料、摘要与主模型补充。重开追问只带一次经理终稿，明确归因才查相关过程 |
| agent-sync 和最终交付 | T2、T3、T5。范围冲突等待，固定候选独立审查，正式组合重验。鹈鹕原文件能在断网浏览器打开，画面方向、截图和版本对应。失败或未知保留真实部分成果 |
| 文档控量 | T7。常用入口有职责和预算。链接、篇幅与语义检查在最终组合版本通过，历史问题与本轮新增问题分别记录 |

方案复核保留一套 Pi 调用、一个 PROJECT 调度器、一个 agent-sync 写入所有者和现有文档检查器。新增的执行机制限于可配置席位、多个就绪项的安全准入和协作承诺核验。现有依赖、版本、岗位和回执继续是事实来源。跨步骤异策略接纳要通过公共接口探针，自主组队要通过真实模型任务，两者均不得由方案文本、模拟分派或单次成功代替。
