## 远端与证据边界

[统一验证工作流](https://github.com/XSY-28/cothink-gui/actions/workflows/gui.yml) 针对 main／PR，从根版本与打包元数据验证 Linux ARM64、Windows x64／ARM64；保留 Node 22.19.0 最低兼容版本，Windows x64另测原生 ConPTY。真实结果以对应源码提交的运行记录为准，本地验证本身不证明远端通过。

[完整 CI 39978528008](https://github.com/XSY-28/cothink-gui/actions/runs/39978528008) 对应源码 `22e9117f5998f62be3b45bb4cba8176924f865d9`，Linux ARM64、Windows x64、Windows ARM64 三个作业均通过。各平台自行从该源码构建并实际安装本平台候选，CLI／GUI 使用同一包。

Windows 终端检查曾将硬编码后端 1 误称 ConPTY；核对固定版本后确认它实际是旧 WinPTY。失败和诊断提交保留，早先标签已更正，不能作为 ConPTY 验收证据。最终入口明确使用 `Backend.ConPTY`（0），直接读取原生通道，在原 40 秒时限内检查重建的可见屏幕、中文多行粘贴不自动提交、实际答案、讨论详情、ONE、保存的任务输入与退出。全部临时 SDK 探针已移除，产品代码和冻结 SDK 未为此改动。

本地 macOS ARM64 最终归档 SHA-256 为 `49361c307c8614148874973119c99612eb52db353605f02095d075f798540dda`。它与上述通过版本的运行源码、GUI、SDK 字节一致；后续变更仅涉及不分发的 Windows 验收脚本。本次验收记录的收尾提交只修改文档，不重复触发同一运行代码的 CI，也不以文档提交的 SHA 冒充已运行的源码 SHA。

所有模型机制测试使用 localhost fixture，项目工作使用固定镜像的实际 Docker。没有调用已配置的付费模型，不据此声称真实模型质量、普遍性能收益、Windows 实体机／Docker、物理中文输入法或跨应用手工体验通过。

冻结 SDK 的生产依赖 audit high、既有 node-domexception 弃用提示和约 707 kB 的 Vite chunk 警告保留；没有自动修依赖。首次 Docker 尚未就绪的基线失败、测试编写中的诊断和旧 actionlint 不识别新 runner 的记录均保留；环境补齐／工具标签说明与实际运行结果分别记录。
